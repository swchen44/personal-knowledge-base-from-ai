# 放大 AI 任務上限

把原始要求改成更值得完成、可驗證且符合使用者限制的任務。保留原需求，提出升級選項；以證據支持能力判斷。

## 起點：留下原始需求

先從對話與可用資料取得真正想達成的成果、受益者、現有方法、不可改的限制、可用資料／工具與成功標準。缺少資料先標示未知；只有會改變方向且無法自行查明的資訊才詢問。

範圍明確時可直接深化方法。使用者需要特定成品或創作控制時，尊重該選擇，不把每件工作升級成自動化系統。

## 四個觀察方向

依任務選擇有價值的方向，其他方向可說明不適用，不硬湊四套方案。

| 方向 | 要找出的改變 | 可核對的產物 |
| --- | --- | --- |
| 速度（Speed） | 減少整體等待、人工接手及重做 | 原方法與候選方法的總時間及相同品質標準 |
| 高度（Altitude） | 從交付物追問它服務的結果，找到值得負責的上一層成果 | 原任務、候選成果、使用者限制與對應驗收 |
| 深度（Depth） | 專家實際採用的原始材料、方法、工具與反證 | 資料需求、專業方法、待檢驗假設與外部判定方式 |
| 廣度（Range） | 把成品名稱改寫為作用，找其他領域可移用的方法 | 來源領域、具體機制、要如何改造及何時不適用 |

高度可逐層探索，但選定目標以資料可得性、可驗證性、時間與權限為界。深度優先改善既有任務，不用增加功能掩飾缺乏證據。跨領域借用方法，不靠扮演專家、虛構訪談或增加 agent 數量。

## 把挑戰目標接到驗證

提出有難度的目標時，同時列出目前基準、指標定義、測量環境、可動用資源、試驗預算與停止／退回條件。沒有數值基準時先量測；臨時數值明記為待同意的候選。

專家方法或領域事實不確定時，查第一手資料；工具、資料或來源不可用時，說明缺口，不模擬取得結果。研究人類目標設定的論文只能作為設計啟發，不能當成此 skill 提升 LLM 表現的實驗證據。

用任務適合的外部訊號驗收，例如可重現測試、獨立資料、留出資料（holdout data）、實際使用者觀察、業務結果或權責者判斷。自我評分與另一個模型的贊同只能提供回饋。資料分析若涉及因果或預測，分清相關與因果，保留未見資料並檢查資料洩漏。

規劃一個成本可控、能否證關鍵假設的最小試驗，與原方法比較。到達約定預算、連續嘗試沒有新證據、重要資料不足或超過權限時，停止該路線並交付結果與替代方案。

## 交付與執行

預設交付一張精簡任務卡，篇幅依工作調整：

1. **原需求與保留限制**：原文要點及目前基準。
2. **建議升級**：選擇哪些方向、具體改善什麼、為何值得。
3. **改寫後任務**：成果、輸入、方法、預期產物、驗收及預算／停止條件，可直接交給人或 AI。
4. **最小試驗**：比較對象、觀察方式、失敗訊號、回復方式。
5. **證據狀態**：已觀察、來源說法、待驗證假設與執行缺口。

使用者只要求改善 prompt 時，交付任務卡即可。已有執行授權時，繼續完成授權範圍內的工作；額外目標、權限、成本及外部副作用分開列為選項，不能從「放大上限」推定已獲授權。

一般不需要分派 subagent。確有可獨立處理的工作時，依目前宿主能力分派具體產物；若要獨立驗證，說明實際隔離機制與驗證範圍。

需要填寫格式、完整案例或讀者手動練習時，讀取 [任務卡與案例](references/task-cards.md)。
