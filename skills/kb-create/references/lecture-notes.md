# 深度講義的編排與驗收

讀者讀完應能說出原作者面對什麼問題、為什麼做這個選擇，以及自己要用什麼證據判斷它有沒有效。以原文的完整論證、案例、數據及限制為材料，用自己的話重組。需要回查的段落在段末附原文連結。

## 從讀者的問題安排章節

先列原文章節、圖號和案例，替每一項找出要回答的讀者問題。保留短 TL;DR，然後用下列順序展開；標題用該篇文章的具體問題命名。

| 讀者想知道 | 講義怎麼寫 |
|---|---|
| 以前到底卡在哪裡？ | 從一個具體任務開始，交代誰在做、依賴什麼知識、失敗有什麼代價。標出作者實例與自擬情境。 |
| 為什麼選這個做法？ | 用 Before / After 表把舊流程的失敗點、新做法、設計意圖一一對上。說明哪些成本轉移給了誰，以及做法成立的前提。 |
| 實際怎麼運作？ | 跟同一個案例走一遍輸入、角色、步驟、交接、輸出與失敗處理。交代讀者從哪裡開始、如何辨認成功。 |
| 作者怎麼知道有改善？ | 還原比較對象、樣本、觀測期間、分母、結果與例外。分清作者已量到的效果、對原因的解讀與未來計畫。 |
| 我如何用在自己的工作？ | 設一個小練習，給起始材料、操作、觀察值、驗收與結果不同時的下一步。已有專案盤點時，沿用原有檢查表。 |

Mermaid 選讀者最難用文字追蹤的關係來畫。流程圖交代人、AI、程式與回饋路徑；比較實驗可畫共同輸入如何分組、盲評與重跑；資料流可畫從哪裡取事件、如何歸因、最後改哪個決策。圖放在解釋它的段落附近，驗證依主檔步驟 4.7。

## 原圖怎麼讀

1. 盤點封面與全部正文圖號，記下原始 URL、實際格式、對應章節與本機相對路徑。排除導覽、作者頭像與推薦文章縮圖。遇到縮圖或轉檔網址，優先取得並確認原始資產。更新舊筆記時比對既有檔案，能沿用就沿用。
2. 打開每張圖，用視覺辨識核對標籤、座標軸、箭頭、數字和註腳。動畫保留原檔，檢視能呈現狀態變化的畫格。缺圖、模糊字或無法確認的數字要具體註記。
3. 在對應章節保留原圖號與中文圖說。每張解釋「畫面上哪個細節值得看 → 它支持哪個論點 → 讀者可據此判斷什麼」。區分圖中可見的事實與編者對意圖的解讀。
4. 使用者指定保留全部原圖時，表格截圖也保留來源檔，另將表格轉成可搜尋的 Markdown。交付前逐號核對引用、檔案格式與動畫；回報原圖、動畫、自製 Mermaid 的數目。

## 指標與 session log 的實作延伸

原文涉及觀測、評估或成本時，先還原作者實際收集的資料、觸發時機、比較方法，以及數字最後改變了哪項決策。接著另列自己的實作口徑。原文沒公布的公式或門檻要標「建議」，不要補寫成作者的做法。

| 每項指標要交代 | 應能回答的問題 |
|---|---|
| 意圖與定義 | 想改善什麼？一筆的單位、分子、分母、時間窗與分組是什麼？ |
| 可取得的證據 | 哪個宿主、版本、事件類型、完整巢狀欄位及配對鍵提供資料？是直接觀測、推定、另接來源，還是未知？ |
| 計算與盲點 | 如何連接呼叫及結果、去除重複列、區分累計與單次用量？缺結果、並行、重試、子代理或版本變動如何影響數字？ |
| 改善與驗收 | 指標升高可能有哪兩種解釋？回看哪一筆案例，改哪個步驟，最後用哪個獨立成果檢查確認？ |

涉及 Codex 與 Claude Code 時，分欄列出兩者在當下版本的事件與欄位。先用實際 JSONL、對應版本的程式碼或官方文件核對，附抽查日期、樣本範圍與版本。查本機紀錄只擷取必要的結構資訊，公開例子用合成資料。模型用量、工具成功、任務驗收各有不同的證據；寫清楚仍缺哪些外部資料。

用一個小案例走完「欄位 → 配對 → 數值 → 決策 → 重測」，再給一個容易算錯的反例。例如同一回應拆成兩列，應該只計一次用量。報告分清讀過欄位、實際跑過解析、兩宿主同題校準，以及尚未驗證的事項。
