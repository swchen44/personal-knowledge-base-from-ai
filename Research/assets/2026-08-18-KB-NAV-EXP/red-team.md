# 階段 4：紅隊自我檢查報告

對象：階段 2 實驗結論＋階段 3 規範 prompt v1.0。逐項攻擊、判定、對策（已修入 v1.1 的條款編號）。

## 攻擊 #1：查詢詞彙偏差（最嚴重）
**攻擊**：出題者＝建樹者＝我。10 題查詢的用詞與檔名/摘要高度重合（「Vercel 的實驗」↔ 檔名 `VERCEL-...`），A 組的 10/10 可能大量來自這種詞彙巧合，高估了「檔名即索引」的普遍性。真實使用者會用口語、錯字、不同語言問。
**判定**：成立。這是本實驗最大的效度威脅。
**對策**：A4（檔名取多樣化同義詞）＋ G20（入庫後用「不含檔名詞彙的改寫查詢」驗證）＋結論降級：「檔名是第一檢索面」保留，但加註「對詞彙不重合查詢的檢索力未測」。

## 攻擊 #2：規模外推
**攻擊**：30 篇的結論外推到 137 篇全庫或未來 500 篇毫無根據；Corpus2Skill 的獲勝規模是 6,221 篇。「不建樹」可能在半年後就是錯的。
**判定**：成立。
**對策**：E16–17 改為**閾值觸發**設計——結論不是「永遠不建樹」而是「條件未達前不建」，並列出三個可觀察的觸發條件。

## 攻擊 #3：統計檢定力為零
**攻擊**：每格 n=1，token 差異（±4k~20k）可能全是取樣雜訊；「X1 省 25%」講得像定律。
**判定**：成立。
**對策**：G22 明訂所有數字為 n=1 參考值須定期重校準；規範條款中數字標【軟】級；報告用語從「證明」改為「單次實測觀察」。

## 攻擊 #4：評分者偏差
**攻擊**：我出題、我建樹、我評分——gold 筆記集是我定義的，「引用命中」的判定也是我。
**判定**：成立（結構性，無法在本輪內消除）。
**對策**：階段 5 由使用者用問卷獨立審查；未來 eval 可用 gstack 筆記中的 planted-fact 方法（在筆記種入已知事實再盲測）。

## 攻擊 #5：導航窄化被低估
**攻擊**：B/C 漏 gold 是在「只有 30 篇、index 描述我親手寫」的最佳條件下發生的。真實維運中 index 摘要品質會劣化，窄化會更嚴重——而規範 v1.0 只把它當註腳。
**判定**：成立。
**對策**：D14 升級為【硬】條款（前 60 字元必含獨有識別碼），G21 加入命中率季度監控作為索引劣化的偵測器。

## 攻擊 #6：規範可執行性
**攻擊**：規範寫得漂亮但無法檢查＝不會被遵守（本 session 稍早才驗證過「軟性指引輸給結構化欄位」的 skill 研究）。
**判定**：部分成立。
**對策**：F 節全部改為可直接執行的 shell 檢查；條款分【硬】【軟】兩級，稽核只報【硬】違規。

## 攻擊 #7：耗時量測污染
**攻擊**：每組 10 個 agent 併發跑，互相搶資源；跨組比較耗時（A 78s vs B 61.5s）可能是併發排程差異。
**判定**：部分成立（組內併發條件相同，組間可比性尚可，但絕對值不可信）。
**對策**：耗時結論降級為方向性參考；summary.md 已列入限制聲明。

## 攻擊 #8：題目難度天花板
**攻擊**：10 題全部「可回答且答案明確存在」——沒有測不可回答題（該答「知識庫沒有」）、沒有測多跳推理陷阱、沒有測幻覺抵抗。三組 10/10 可能只證明題目太簡單。
**判定**：成立。
**對策**：記入下輪計畫（與 Corpus2Skill 實跑合併）：加入 unanswerable 題與干擾題；本輪結論範圍限定為「可回答的檢索型查詢」。

## 修正總結
v1.0 → v1.1 變更：新增 A4、G 節全部（20–22）；D14 升【硬】；E16 改閾值觸發表述；F 節 shell 化；全文數字標註【硬/軟】等級。

## 殘留風險（無法在本輪解決，明示給使用者）
1. 評分者偏差（攻擊 #4）——等使用者問卷。
2. 詞彙偏差的量化程度未知（攻擊 #1 只能緩解、不能在本輪測量）。
3. 50 篇閾值是推測值，不是實測值。

# 補充實驗 D 系列（回應攻擊 #4/#8 的污染疑慮；2026-08-18）

## D1 對話隔離探測：✅ context 隔離證實
subagent 三題「對話專屬事實」全部答「context 中沒有這項資訊」，並列出它實際收到的內容：系統提示、CLAUDE.md、MEMORY.md 索引、git 狀態、工具清單、任務訊息。**主對話不會被動洩漏給 QA agents。**
次要發現：MEMORY.md 索引會注入每個 subagent——是一條小的跨 session 資訊通道（本實驗中只有 mermaid 教訓一條，無害，但嚴格實驗應清空或審視 memory 內容）。

## D2 transcript 磁碟可及性：⚠️ 隔離只在 context 層
subagent 成功定位並讀取主 session transcript（~/.claude/projects/.../<session-id>.jsonl，5.1MB，-rw------- 同使用者可讀）。結論：**「context 隔離但磁碟可及」**——任何有 Bash/Read 的 subagent 都有能力讀對話紀錄，本實驗的隔離依靠「預設 context 邊界＋prompt 指示」，非硬隔離。
對本實驗效度的影響：QA agents 沒有動機也沒有跡象去讀 transcript（引用全部指向 corpus 檔案且附本文細節如行號），主結論不受影響；但**嚴格實驗要 OS 層 sandbox 或獨立環境**。

## D0 先驗知識基線：量化污染程度
無工具、純先驗作答 10 題：
- Sonnet：嚴格 0/10（5 題直答不知道、4 題模糊猜測、1 題方向對）
- Fable：約 1 題全對（F4 Stanford 20%——連論文名都記得，公開研究屬預訓練污染）＋2 題部分（S1 skill 原則、X1 Yegge 主張——公開知識）
**修正後結論**：10 題中 7–8 題（KB 特有事實：Codex 1024、OTel 8 個、gstack 三層、一人公司分工等）先驗不可答，三組 10/10 的檢索有效性成立；F4 與部分 S1/X1 的「正確」含先驗成分，未來出題須排除公開新聞型事實。

bwrap 為 Linux 專用，本機 macOS 不存在；等效物 `sandbox-exec`（Seatbelt）實測成功：

→ transcript 被拒讀、corpus 照常可讀。未來嚴格實驗以此 wrapper 包 agent 指令即可硬隔離（D2 缺口補上）。

# 攻擊 #9：同樹污染（由使用者發現，2026-08-18 第三輪）

**攻擊**：results/（含前組答案）、governance-prompt、paper-report 與 corpus 同住 kb-exp 樹；B/C/E 組的指示「嚴禁讀 kb-exp 以外」字面上允許讀 kb-exp/results/。B 組開跑時 arm-A.md 已存在——洩漏通道真實存在。

# 攻擊 #10：題目-檔名主題對齊偏差（由使用者發現，2026-08-19 第四輪）

**攻擊**：「是不是題目太簡單，任何題目都會命中檔名？」盤點成立——主實驗 10 題 gold 檔名全部與題目主題對齊；E1 只測詞彙不重合、未測主題不重合。
**補測（實驗 F）**：6 題埋藏型×A/B=12 runs → 12/12 全對，但成本 +41%（詳 arm-F.md）。
**判定**：部分成立、方向出乎意料——「太簡單」在正確率維度不成立、在成本維度成立。
**認知更新**：檔名決定成本而非正確率；天花板效應根源是「規模小到全文可掃」；埋藏事實的檢索溢價是「該浮升到 INDEX 摘要」的治理訊號。
**方法論**：審查者連續發現 #9/#10 兩個作者盲點——評分者偏差（#4）的最佳緩解就是真實的外部審查。
