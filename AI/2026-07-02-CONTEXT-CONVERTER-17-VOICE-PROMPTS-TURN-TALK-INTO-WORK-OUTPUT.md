## 摘要（Summary）

這是 Gary Chen 個人網站 Playbook 上的一組「Prompt Set」，配套他另一篇談語音輸入與 context 轉換的 Patreon 文章。該文章把知識工作拆成 5 種 context 轉換原型：**收斂、平移、升格、濃縮、反問**，外加一個叫**解碼**的小動作。這 17 個 prompt 不是要複製貼上的長 prompt，而是設計成可以直接用嘴巴說出口的簡短指令，搭配 Typeless 的 Ask 功能（選取口述文字、觸發 Ask、說出對應 prompt）使用，也能用在任何可對選取文字下指令的 AI（Claude、ChatGPT 等）。

每個 prompt 的價值不在動作本身，而在於它把「內行才知道的成功因子」與「輸出格式」壓縮進一句話裡——一封好 email 該怎麼排、一份 PRD 該有哪五段、一個 bug report 要能重現，說一句話就全部繼承。所有 prompt 共同遵守一條 **fidelity（忠實度）底線**：只重塑使用者講過的內容，缺漏的資訊用括號標出讓使用者自己補，絕不無中生有。

## 關鍵洞察（Key Insights）

- **簡短口語指令 vs 長 prompt**：這組工具刻意設計成「一句話說得出口」的長度，降低語音輸入場景下的使用摩擦，這與大多數需要複製貼上的長 prompt 模板形成對比。
- **Fidelity 底線是核心設計原則**：所有 17 個 prompt 都不允許 AI 自行腦補或杜撰缺漏資訊，一律用括號標出讓使用者回頭補完，這是避免語音轉文字流程中「幻覺（Hallucination）」污染輸出的關鍵機制。
- **職能分組降低選擇成本**：通用三個（意圖補洞、白話解碼、口語升格）天天用得到；其餘依職能分 A（工程師）、B（PM）、C（創辦人／主管）、D（學習者），讓使用者不必在 17 個選項中每次重新判斷該用哪一個。
- **括號是設計出來的功能，不是缺陷**：AI 主動用括號標出使用者沒講清楚的地方（收件人、期限、負責人等），這個「反問」動作本身被當成一種可重複使用的 context 轉換原型。
- **意圖補洞（Prompt 1）建議當作固定前置動作**：作者明確建議在送出任何重要指令給 AI 之前，先用 Intent Gap Finder 審一遍，這是一種「先校準意圖，再產出」的工作流慣例。

## 詳細內容（Details）

### 這組工具的定位

配套文章把知識工作拆成 5 種 context 轉換原型：**收斂（converge）、平移（translate）、升格（elevate）、濃縮（condense）、反問（interrogate）**，外加一個叫**解碼（decode）**的小動作。17 個 prompt 各自標註了自己屬於哪個原型（如〔收斂〕〔反問〕〔升格〕〔平移〕〔濃縮〕〔解碼〕），方便對照原文的分類架構。

> [!tip] 使用提示
> 這些 prompt 設計給 Typeless 的 Ask 功能：選取口述好的文字，觸發 Ask（預設 Ctrl + Space），把 prompt 說出來或貼上，一次轉好。也能直接用在 Claude、ChatGPT 等任何 AI，把 prompt 跟內容一起貼上即可。coding 相關的（Prompt 4、5、6）產出貼到 Claude Code、Codex、Cursor 最順。

### 怎麼用這組 prompt

- **基本動作**：先用 Typeless 把想法口述成文字，選取它，觸發 Ask，說出對應的 prompt。
- **先看通用三個**：意圖補洞、白話解碼、口語升格，不分職能天天用得到。其中意圖補洞建議當成送出任何重要指令前的固定前置動作。
- **再跳職能分組**：工程師看 A 組、PM 看 B 組、創辦人與主管看 C 組、學習者看 D 組。
- **看到括號別緊張**：那是 prompt 故意讓 AI 標出漏講的地方，補上再跑一次，產出就完整了。

> [!note] Fidelity 底線
> 所有 prompt 只重塑使用者講過的內容，缺的用括號標使用者補，絕不無中生有。這是貫穿整組工具最重要的一條隱性規則。

### 通用（每個人都用得到）

#### Prompt 1：Intent Gap Finder（意圖補洞）〔反問〕

**功能**：找出需求裡沒講清楚的洞。關鍵：用最挑剔的字面執行者角度看、把缺口分成目標／限制／範圍／驗收標準四類、只標不補讓使用者自己填。

**什麼時候用**：送出任何重要指令給 AI 之前，選取剛口述的需求跑一遍。

**你會拿到**：需求原文，加上分類的括號標注，指出漏掉的目標／限制／範圍／驗收標準。

**可以接到哪**：任何產出型 prompt 的前置（先補完意圖再轉換）。

**AI 會問你**：它會用括號標出目標不明的地方、限制或禁區沒講的地方、範圍模糊或驗收標準缺席的地方。

```
這是我要給 AI 的需求。用一個最挑剔、只照字面做事的執行者角度審一遍，把我沒講清楚、會讓它亂猜的地方用括號標出來，並標出每個缺口是缺了目標、限制、範圍、還是驗收標準，順便一句話說為什麼要補。不要幫我補答案，只標出來讓我自己填。
```

#### Prompt 2：Jargon Decoder（白話解碼）〔解碼〕

**功能**：把看不懂的名詞翻成白話。關鍵：白話加一個生活比喻（不用術語解釋術語）、附「什麼時候要緊、什麼時候可略過」讓使用者能判斷，而不只是丟定義。

**什麼時候用**：工作中撞到看不懂的名詞或報錯，不想切出去查斷了心流。

**你會拿到**：一句白話解釋加一個比喻，附「什麼時候要緊、什麼時候可略過」讓使用者自己判斷該不該理它。

**可以接到哪**：獨立使用。

**AI 會問你**：如果這個詞有多個意思，它會先問指的是哪一個。

```
用白話加一個生活化的比喻解釋這個名詞是什麼，不要用更多術語。然後告訴我它通常在什麼情況下要緊、什麼情況可以先略過，讓我自己判斷現在該不該理它。
```

#### Prompt 3：Voice-to-Professional Writer（口語升格）〔升格〕

**功能**：把口述升格成專業書面。關鍵：BLUF（Bottom Line Up Front，開頭先講重點）開頭就講重點、要對方做的事寫具體、短段落好掃、保留原本語氣、缺的資訊用括號標補。

**什麼時候用**：知道大概要講什麼、但懶得斟酌字句排版時，口述完直接升格。

**你會拿到**：排好、語氣對、可直接送出的專業書面，缺的欄位用括號標補。

**可以接到哪**：獨立使用。

**AI 會問你**：收件人或對象是誰（沒說的話）、有沒有期限（沒說會用括號標補）、要 email、訊息還是公告。

```
把我剛講的，升格成一封專業的 email（或訊息、公告），保留我原本的語氣。第一句就講重點跟我要對方做什麼，不要鋪陳；要對方做的事寫清楚具體；段落短、一段一個重點。只用我講過的內容，不要加任何我沒說的承諾或客套；少了關鍵資訊（像收件人或期限）就用括號標我補。
```

### A. 工程師 / AI Builder

#### Prompt 4：Spec-to-Agent Prompt Builder（需求轉指令）〔平移〕

**功能**：把功能想法變成 coding agent 指令。關鍵：目標寫成可觀察的完成狀態、標出範圍、明確列出不能碰的禁區、給可檢查的完成訊號。

**什麼時候用**：想到一個功能或改動，要丟給 Claude Code、Codex、Cursor 之前。

**你會拿到**：一段可貼給 coding agent 的指令：目標、範圍、禁區、完成訊號，缺的用括號標補。

**可以接到哪**：coding agent（Claude Code、Codex、Cursor agent mode）。

**AI 會問你**：不能碰的禁區有哪些（沒講的話）、怎麼算做完（完成訊號）、動到哪些檔案或範圍。

```
把我剛講的功能想法，整理成一段給 coding agent 的清楚指令，分成：目標（做完後可觀察到的變化）、範圍（動哪些檔案或模組）、禁區（明確列出不能碰的，像 public API、既有測試、DB schema）、完成訊號（怎麼算做完，像測試過、tsc 無錯）。我沒講到的用括號標我補，不要自己編。
```

#### Prompt 5：Review-to-Revision Translator（吐槽轉指令）〔收斂〕

**功能**：把口頭吐槽變成 agent 修改指令。關鍵：每點拆「改什麼／為什麼／期望」、按檔案分組、明確標出這輪不要動的部分。

**什麼時候用**：看著 AI 的產出有一堆口頭 feedback，想直接變成下一輪的修改指令。

**你會拿到**：一份按檔案分組的修改指令清單，每點含改什麼／為什麼／期望，外加一張「這輪別碰」清單。

**可以接到哪**：coding agent（Claude Code、Codex、Cursor agent mode）。

**AI 會問你**：這輪哪些部分不要動（有提就列成別碰清單）、每個吐槽對應哪個檔案或區塊。

```
把我剛講的、對這個產出的所有吐槽，整理成給 coding agent 的修改指令。每一點拆成「改什麼、為什麼（我的意圖）、期望變成怎樣」，並按檔案或區塊分組。我有講到不要動的部分，另外列成一張「這輪別碰」清單。只根據我講的，不要自己加改動。
```

#### Prompt 6：Bug Report Builder（Bug 回報）〔收斂〕

**功能**：把口述的問題變成 bug report。關鍵：能重現才有用，編號重現步驟、預期跟實際分開寫、附環境。

**什麼時候用**：踩到 bug 想記錄或回報，但懶得自己寫成規整的 report。

**你會拿到**：一份標準 bug report：重現步驟、預期、實際、環境，缺的用括號標補。

**可以接到哪**：issue tracker 或 coding agent。

**AI 會問你**：缺的重現步驟、環境（版本、系統、瀏覽器，沒講的話）、預期結果（如果沒講清楚）。

```
把我剛講的問題整理成一份 bug report：編號的重現步驟、預期結果、實際結果（這兩個分開寫）、環境（版本、系統、瀏覽器）。少了哪個重現需要的資訊，用括號標出來問我，不要自己腦補步驟。
```

### B. 產品經理（PM）

#### Prompt 7：Meeting-to-PRD Writer（會議轉 PRD）〔收斂〕

**功能**：把會議整理成 PRD。關鍵：五段結構（背景／目標／需求／非目標／開放問題）、目標要可衡量、非目標擋範圍蔓延、開放問題攤出未決。

**什麼時候用**：開完會或有個功能構想，要變成一份給團隊看的 PRD。

**你會拿到**：一份結構化 PRD：背景、目標、需求、非目標、開放問題。

**可以接到哪**：獨立使用。

**AI 會問你**：可衡量的成功指標（沒講的話）、這次的非目標、還沒決定的開放問題。

```
把我剛講的整理成一份 PRD，分成背景、目標（附一個能衡量成功的指標）、需求、非目標（明確寫這次不做什麼）、開放問題（還沒決定的）。我沒講到的關鍵欄位用括號標我補，不要自己編需求或指標。
```

#### Prompt 8：User Story Extractor（回饋轉 Story）〔收斂〕

**功能**：把雜亂回饋整理成 user stories。關鍵：轉成標準格式、相同底層需求合併去重、刻意不排優先級（那需要產品判斷）。

**什麼時候用**：手上一堆訪談、客服、問卷回饋，想變成團隊能用的 user stories。

**你會拿到**：一組合併去重的 user stories（標準格式），刻意不含優先級。

**可以接到哪**：Prompt 7 Meeting-to-PRD Writer（user stories 可當 PRD 的需求輸入）。

**AI 會問你**：太模糊、變不成 story 的回饋（會列出來讓使用者補）、角色不清楚的回饋。

```
把我剛講的這堆用戶回饋，整理成標準的 user story 格式（As a 某角色, I want 某能力, so that 某好處）。講到同一個底層需求的合併成一則，不要重複。不要幫我排優先級。太模糊、變不成 story 的，另外列出來讓我補。
```

### C. 創辦人 / 主管

#### Prompt 9：Weekly Update Writer（週報）〔濃縮〕

**功能**：把一週進展濃縮成週報。關鍵：完成／進行中／受阻／下週四桶、受阻寫清楚缺什麼要誰幫、誠實不灌水。

**什麼時候用**：週末或週一要交團隊週報，不想自己重新回想整理。

**你會拿到**：一份四桶週報：完成、進行中、受阻或需協助、下週重點。

**可以接到哪**：獨立使用。

**AI 會問你**：受阻的項目需要誰幫忙（沒點名的話）。

```
把我剛講的這週進展，濃縮成一份週報，分成完成、進行中、受阻或需要協助、下週重點。受阻的地方寫清楚缺什麼、要誰幫忙。每點精簡好掃，只用我講的，卡住的不要美化成順利。
```

#### Prompt 10：Decision Log Writer（決策記錄）〔收斂〕

**功能**：把討論整理成決策記錄。關鍵：已定案跟未決分開、每個決定附一句理由、action items 附負責人加期限。

**什麼時候用**：開完有做決定的會或一對一，想把結論固定下來不失憶。

**你會拿到**：一份決策記錄：決定加理由、action items 含負責人與期限、待跟進。

**可以接到哪**：獨立使用。

**AI 會問你**：每個 action item 的負責人（沒講的話）、期限、哪些其實還沒定案。

```
把我剛講的討論，整理成一份決策記錄。分成：已定案的決定（每個附一句為什麼這樣決定）、action items（每個附負責人跟期限）、還沒定案的待跟進。已定跟還在討論的要分清楚。負責人或期限我沒講的，用括號標我補，不要自己指派。
```

#### Prompt 11：Interview Evidence Logger（面試記錄）〔收斂〕

**功能**：把面試對話整理成證據。關鍵：只記事實與引述、按能力項分類、不評分不下結論、標出證據不足的項。

**什麼時候用**：面試完，想把對話整理成有結構、之後好跟其他面試官比對的記錄。

**你會拿到**：一份按能力項分類的訪談證據記錄，只有事實與引述、不含評分。

**可以接到哪**：獨立使用。

**AI 會問你**：關心哪幾個能力項（沒講就用溝通／問題解決／技術深度）、這次沒問到的能力項會被標出來。

```
把我剛講的面試對話，按能力項（像溝通、問題解決、技術深度）分類整理成證據。每一項下面只記候選人實際說了什麼、做了什麼，用引述或客觀描述，不要評分、不要下錄取結論。有哪個能力項我這次沒問到，標出來。
```

#### Prompt 12：Strategy Memo Writer（策略備忘）〔收斂〕

**功能**：把想清楚的策略整理成團隊方向文件。關鍵：要做什麼／為什麼（含取捨）／不做什麼、忠實呈現不替使用者做新決策。

**什麼時候用**：腦中已有清楚方向，要變成一份對齊團隊的文件。

**你會拿到**：一份團隊方向文件：要做什麼、為什麼、不做什麼、對團隊的意涵。

**可以接到哪**：獨立使用。

**AI 會問你**：取捨的理由（沒講清楚的話）、明確的非目標、對團隊的實際意涵。

```
把我剛講的策略，整理成一份給團隊的方向文件，分成：我們要做什麼、為什麼（包含我提到的取捨跟放棄的選項）、我們不做什麼、對團隊的實際意涵。忠實照我講的，不要幫我做新的策略決定，我沒講清楚的用括號標我補。
```

### D. 學習者 / 研究者

#### Prompt 13：Reading Digest Builder（讀後摘要）〔濃縮〕

**功能**：把長文濃縮成摘要加疑問。關鍵：核心主張加證據加結論、追問鎖定它的缺口與可延伸處、不問已回答的。

**什麼時候用**：讀完（或懶得細讀）一篇長文論文，想快速抓重點又不流於表面。

**你會拿到**：一段摘要（核心主張／證據／結論），加 3 到 5 個該追問的問題。

**可以接到哪**：Prompt 15 Idea-to-Outline Builder（追問可以長成你要寫的東西）。

**AI 會問你**：選取要濃縮的完整文章或段落再跑。

```
把我選取的這篇濃縮成：核心主張、它用什麼證據或方法支撐、結論。然後列 3 到 5 個我讀完該追問的問題，鎖定它沒講清楚、證據薄弱、或值得延伸的地方，不要問文章已經回答的。
```

#### Prompt 14：Lecture Notes Structurer（課堂筆記）〔收斂〕

**功能**：把課堂內容整理成結構化筆記。關鍵：分層要點（主點加支撐）、抓例子與金句、把待辦跟講者內容分開。

**什麼時候用**：上完課、聽完演講或 podcast，想整理成能複習能行動的筆記。

**你會拿到**：一份結構化筆記：主題、分層要點、例子金句、待辦。

**可以接到哪**：獨立使用。

**AI 會問你**：把要整理的課堂內容口述完整或貼上再跑。

```
把我剛講的（或錄下的）這段課堂內容，整理成結構化筆記：主題、分層的關鍵要點（主要點底下掛支撐細節）、值得記的例子或金句。如果我有講到自己想採取的行動或想之後查的，另外獨立列成一張待辦，跟講者的內容分開。只整理我講到的。
```

#### Prompt 15：Idea-to-Outline Builder（想法轉大綱）〔收斂〕

**功能**：把零散想法整理成大綱。關鍵：先定一句主線論點、段落照論點推進、離題的好想法標「可另開」不硬塞。

**什麼時候用**：對某主題有很多想法但很散，想變成一份能開始寫的大綱。

**你會拿到**：一份大綱：一句主線論點、推進的段落小標與支撐點，外加「可另開」清單。

**可以接到哪**：獨立使用。

**AI 會問你**：主線論點（看不出單一主線時，會給幾個選項挑）、這份大綱給誰看。

```
把我剛講的這些零散想法，整理成一份大綱。先幫我抓出一句主線論點，再把想法排成推進的段落（每段一個小標加底下的支撐點）。有想法很好但離主線的，另外標成「可另開」，不要硬塞進來。如果看不出明確主線，給我兩三個可能的主線讓我選，不要自己硬定一個。
```

### 生活場景

#### Prompt 16：Heartfelt Letter Writer（升格情書）〔升格〕

**功能**：把說出口的真心話升格成一封信。關鍵：保留講的具體回憶跟原本語氣、升格成信的結構、絕不加浪漫套話或沒說的。

**什麼時候用**：有想對某人說的話，講得出來但寫不出來，想變成一封信。

**你會拿到**：一封保留原話與語氣的信，缺的稱謂用括號標補。

**可以接到哪**：獨立使用。

**AI 會問你**：稱謂、寫給誰（沒說的話）、什麼場合：生日、道歉、感謝。

```
把我剛講的這些話，升格成一封信，保留我講到的每個具體的事、回憶跟我原本的語氣。整理成信的結構（開頭、內容、收尾），但絕對不要幫我加任何浪漫套話或我沒說的感情。稱謂或對象我沒講的，用括號標我補。
```

#### Prompt 17：Idea-to-One-Pager Builder（點子轉提案）〔收斂〕

**功能**：把一個點子整理成創業 one-pager。關鍵：問題（含現在怎麼將就）／對象／解法／為什麼是你／下一步驗證、沒想清楚的標「待驗證」。

**什麼時候用**：有個還很粗的點子，想趁記得固定成一頁，之後才好判斷值不值得做。

**你會拿到**：一頁創業 one-pager：問題、對象、解法、為什麼是你、下一步，沒想清楚的標「待驗證」。

**可以接到哪**：獨立使用。

**AI 會問你**：為什麼是你來做（沒講清楚會標出來，這是最常見的致命缺口）、現在大家怎麼將就這個問題、下一步要驗證什麼。

```
把我剛講的這個點子，整理成一頁創業 one-pager，分成：問題（包含現在大家怎麼將就）、目標對象、解法、為什麼是我來做（我的獨特優勢）、下一步該驗證什麼。我還沒想清楚或還是假設的部分，標成「待驗證」，不要幫我編出市場數據或優勢。
```

## 我的心得（My Takeaways）

這組工具最有價值的地方不是 17 個 prompt 本身的文案，而是它示範了「prompt 工程」在語音輸入場景下應該長什麼樣子：**短到可以脫口而出，但結構嚴謹到能鎖住輸出格式**。這跟一般部落格常見的長篇 mega-prompt（動辄上百行的系統提示詞）走的是完全相反的路線，更貼近日常高頻使用的場景，而不是一次性的複雜任務。

我認為 Prompt 1（Intent Gap Finder）作為固定前置動作最值得立刻採用——多數人跟 AI 協作的失敗，其實不是模型能力不足，而是需求本身就沒講清楚，模型只能亂猜。把「反問」變成一個可重複使用的習慣性步驟，而不是等產出錯了才回頭補充，這跟 [[2026-05-25-HUMAN-SOP-TO-AGENTIC-WORKFLOW-PROMPT-TOOLKIT]] 裡「越資深的人，判斷越容易被壓縮成默會知識，第一版 SOP 越容易翻車」是同一個問題的不同解法：一個是流程設計層面先拆解，這個是單次對話層面先反問。

## 待補充（Open Questions）

- **Fidelity 底線在多輪對話中是否還能維持？** 這些 prompt 都是單輪設計（口述一次、轉換一次），若使用者持續追加口述內容，AI 是否還能準確分辨「新資訊」與「舊資訊該不該覆蓋」，原文沒有討論。可追蹤：`multi-turn voice dictation context fidelity prompt design`
- **括號標注的資訊，使用者真的會回頭補嗎？** 這套設計假設使用者看到括號會主動補完再重跑，但若使用者略過括號直接使用產出，會不會反而放大了「看起來完整、其實有缺口」的風險？可追蹤：`bracketed placeholder prompt user compliance research`
- **17 個 prompt 之間有沒有更完整的組合鏈路？** 文章只點出 Prompt 7↔8、13↔15 兩組可以串接，其餘 14 個 prompt 之間是否有更多可鏈結的組合，原文沒有系統性說明。可追蹤：`gary chen context converter prompt chaining`
- **這套方法只驗證於 Typeless，換成其他語音輸入工具（如 Whisper 即時轉錄、系統內建聽寫）效果是否一致？** 原文提到「也能用在任何可對選取文字下指令的 AI」，但沒有交代語音辨識品質（斷句、口誤率）對這些 prompt 效果的影響。可追蹤：`voice dictation accuracy impact llm prompt post-processing`
- **配套的 Patreon 原文（context 轉換五原型：收斂、平移、升格、濃縮、反問）尚未收錄進知識庫**，這篇 prompt 集只是實作層，理論層的完整論述還缺一篇筆記。可追蹤：`Gary Chen context shift patreon 收斂 平移 升格 濃縮 反問`
